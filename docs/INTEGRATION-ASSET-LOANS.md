# 独立接入记录：物资借用检查工具

这是维护者完成的工程接入验证，不是外部用户试用，也不是正式库存应用。核心库保持0.2.0，未新增核心API。

## 接入方式

独立目录 `examples/asset-loans` 自带 moon.mod、moon.pkg 和 Node 主机；固定依赖公开注册表 `Kleinrat/frictionless@0.2.0`。自动检查将它复制到仓库外临时目录，不创建 moon.work，不借用父仓库源文件或构建产物，重新安装、检查和构建。

## 可复现流程与结果

- 从合成物资/借用CSV生成两表规则草稿：前导零编号保留文本，采样提示保留在元数据中。
- 用明确编写的 `reviewed-rules.json` 演示人工补全必填、主键、数量下限及物资引用；不是推断器自动猜出业务规则。
- 正确包通过；不存在的物资、重复借用编号、数量0分别得到 foreign-key、primary-key-duplicate、minimum；无效包禁止导出。
- 在临时副本修复后通过，导出字节与规则文件一致，导出包重新校验及官方Frictionless读取通过。
- JSON申请字段检查：数量0失败；物资999和较大数量仍可能通过字段检查，输出scope明确不代表物资存在、库存可用或借用编号唯一。
- 已有输出目标拒绝覆盖；原合成数据不变。

## 接入中明确的限制

| 卡点 | 处理与剩余范围 |
|---|---|
| 草稿缺主外键和业务约束 | 由人确认并补充规则，提供对照模板 |
| JSON仅有单表入口 | 本应用只提供申请字段检查，跨表关联继续走CSV包；不冒充JSON包级校验 |
| 数据完整读入 | 单文件16MiB上限；采样不等于流式读取，不用于大文件服务 |
| 通用校验不等于业务库存引擎 | 不扣库存、不处理归还/预约/并发，也不判断历史借用数量之和 |

运行验证：`python scripts/test_asset_consumer.py --reference`（需要Node22+、MoonBit和Frictionless5.21.0）；CI安装参考工具后执行。核心原有50项测试继续通过。
